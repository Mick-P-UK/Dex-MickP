## Summary

Simon (Systems Made Better) shows how to make a Claude "Cowork OS" work across
desktop and mobile by moving the source of truth off local-only files. The problem: local
folders sync one way only (desktop-out), and mobile Claude cannot reach them, so on the
phone Claude is "just another generic Claude". His two-layer fix: (1) publish identity
files (about-me, voice profile, writing rules) as account-level Claude skills, which attach
to the account and so travel to every device; (2) put the larger, frequently-changing
context/memory/project files in cloud storage Claude can read - locally when the desktop is
on, or via a connector on mobile (he chooses Dropbox for its offline sync and file-level
editing). He migrates the folder to Dropbox, updates CLAUDE.md and the global instructions
with an "identity gate" (load about-me, or the identity skills if files are unreachable,
before acting) and the Dropbox path, then sets up a second machine. He also warns that
folder-linked Cowork projects stay local and do not sync, so he uses projects only to group
chats - starring the top-level Cowork folder and letting Claude navigate to subfolders.

## Key Takeaways

- Problem: local files sync one way (desktop only); mobile Claude cannot reach them, so
  it loses your context and personalisation.
- Fix layer 1 - identity as skills: turn about-me, voice profile and writing rules into
  account-level Claude skills; skills attach to your account, not a machine, so they
  travel everywhere.
- Fix layer 2 - context in the cloud: put memory/project files in cloud storage (he picks
  Dropbox for built-in offline sync and file-level editing via its MCP connector); Claude
  reads them locally on desktop or via the connector on mobile.
- Add an "identity gate" to CLAUDE.md / global instructions: load about-me (or the identity
  skills if the files are unreachable) before doing anything else.
- Scheduled tasks: local-computer tasks only run while the machine is awake; deselect a
  working folder to be allowed to move a task to the cloud; set auto-approval so unattended
  tasks complete.
- Cowork projects: a folder-linked project stays local and will not sync/share - so use
  projects only to group chats, star the top-level folder, and let Claude navigate to
  project subfolders for a single synced source of truth.
- Bonus: keeping generic root CLAUDE.md files means you could move the whole system to
  another LLM later (rename to agents.md etc.).
- Relevance to us: highly relevant to Mick's own cross-device Cowork/Dex setup and the
  mirror-and-skills discussion - it is the same "skills travel, files need a connector"
  problem.
