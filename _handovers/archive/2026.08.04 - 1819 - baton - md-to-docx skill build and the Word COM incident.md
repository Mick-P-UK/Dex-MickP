## Decisions made

- The HOC Word document omits the YAML frontmatter. It is machine metadata
  (pipeline version, notebook ID, audit_status), not reader-facing. `--frontmatter`
  exists if Mick ever wants it.
- The throwaway converter was promoted to a skill rather than left in scratchpad -
  every Ron report needs a DOCX, and SOP #6 already promises markdown + DOCX + PDF.
- DOCX-to-PDF is a SECOND ENTRY POINT inside md-to-docx, NOT a separate skill.
  Reasoning Mick accepted: 50-plus skills means discovery, not capability, is the
  bottleneck; a `docx-to-pdf` sitting beside `md-to-docx` is exactly the pair that
  gets mis-picked (the CREI failure of 2026-07-22); and two copies of the same Word
  COM logic drift apart. `md_to_docx.py --pdf` imports `convert_one()` from
  `docx_to_pdf.py`, so there is one implementation.
- PDF export uses Word's `ExportAsFixedFormat`, not `SaveAs(FileFormat=17)`, so PDFs
  carry bookmarks built from the Word headings, plus tagging and doc properties.
  Verified: 12 headings became 12 correctly nested bookmarks on the HOC report.
- Word is started with `DispatchEx`, never `Dispatch` - see the incident below.
  This must not be reverted.
- The converter's ASCII pass EXEMPTS the pound and cent signs, matching the
  non-ascii-sweep REVIEW_IGNORE decision of 2026-08-02, and reports anything else
  with line numbers rather than silently altering it.
- Both scripts are themselves pure ASCII (the typographic mapping table uses \u
  escapes) so they never become false positives in the weekly vault sweep.

## The Word COM incident (read this before touching any Word automation)

Mick reported Word "closing of its own accord" during the session. It was Cedric.
Word registers as a SINGLE-INSTANCE COM server, so `Dispatch("Word.Application")`
and PowerShell's `New-Object -ComObject Word.Application` do not start a new Word -
they ATTACH to the one Mick already has open. The scripts then called `Quit()`,
closing his session, and with `DisplayAlerts = 0` any save prompt was suppressed.
Window: roughly 16:39 (a page-count check) and several times between 17:50 and 18:05.

Two fixes applied and verified:
1. `open_word()` now uses `DispatchEx`, which forces a private instance the script
   can only ever close itself. Commented in the code so it is not "tidied" back.
2. The SKILL.md verification step had been RECOMMENDING the unsafe PowerShell
   snippet. Replaced with a python-docx structural check that never launches Word,
   plus an explicit do-not-do-this warning citing this incident.

Damage check run at the time: no saved .docx anywhere under Documents was altered
(only the HOC file Cedric created); the single Word AutoRecover file present dates
from 13:11, before any of the activity. Mick was asked to check anything he had
open and unsaved in that window.
