## Part 2 - Portico ShareScope capture (hardened; one caveat)

ROOT CAUSES found by driving ShareScope live (all now in
ShareScope-data-cmd-Reference.md under "View-state verification"):

1. "Current holdings" (data-cmd ViewCurrentOnly) is a TOGGLE (current <-> full),
   NOT a set-to-current, and each portfolio REMEMBERS its own state. An
   unconditional click sent PP1 (remembered ON) to full and PP2 (remembered OFF)
   to current - the whole "PP1 wrong / PP2 right" mystery.
2. The button 'active' class is USELESS - it sits on BOTH Holdings and
   Current-holdings buttons at once. The reliable signal is which grid caption is
   actually PAINTED: 'List of current holdings' vs 'List of holdings'.
3. The view must be read only AFTER the list has finished loading. PP1's long list
   can take ~3s to render in a fresh browser context; reading during load catches
   a lingering caption and mis-decides.
4. Portfolio SELECTION was fire-and-hope. Now matched by 'PPx (UK)' EXCLUDING the
   'Port:' indicator (data-cmd=CurPort) and CONFIRMED against the panel header
   ('Transactions for Portfolio: ... PPx (UK)') with retries; raises on failure.

FIXES in sharescope_portico.py (all compile+ASCII clean, in the vault):
- select_portfolio: verified + retrying (validated live: PP2->PP1 header tracked).
- ensure_current_holdings: toggle-aware (only toggle when the settled view is full),
  caption-painted verification, network-idle settle before reading, stable re-check.
- capture_panel: final guard re-verifies current-holdings right before the screenshot.

CAVEAT / OPEN: on a SLOW page load (18:39 run) the caption did not paint within the
retries and PP1 still captured the full list (verified by eye). PP2 is reliable.
So the capture is much better but NOT yet 100% under slow loads. Recommended next
fix: replace/augment the caption signal with a load-independent one - detect
CLOSED positions in the grid (rows with Shares=0) which appear ONLY in the full
view; grid rows are DOM-readable as div.list-row inside div.list-content-fixed
(row text like "4EDVEndeavour Mining PLC"). Or simply retry the whole capture when
the run reports the "current-holdings view NOT confirmed" error flag.

## Key learnings (record in memory)

- DRIVE THE REAL UI EARLY. Five blind reruns taught less than one live Playwright
  session. When a headed-UI automation misbehaves and you can control it, observe
  it live rather than patch-and-ask.
- VERIFY THE SETTLED, RENDERED RESULT - never trust a click or a momentary signal.
- KNOW THE CONTROL SEMANTICS before automating (a toggle is not a switch; state can
  be remembered per context). A stable data-cmd selector is necessary, not sufficient.
- WHEN DOM AND PIXELS DISAGREE, THE PIXELS ARE GROUND TRUTH.
- FAIL LOUD: every action with an outcome should verify, retry, then raise/flag.
