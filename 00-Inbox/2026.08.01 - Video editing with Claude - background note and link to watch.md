=====================================================
THE ONE THING TO UNDERSTAND FIRST
=====================================================
Claude does not edit video. It writes and runs the commands that edit
video. That distinction governs everything else.

There are two layers:
- The DECISION layer. What to cut, what order, which 30 seconds make a
short. This is the judgement work, and it is where Claude is genuinely
good, because it reads the transcript rather than watching the footage.
- The EXECUTION layer. FFmpeg, a free command-line tool, does the actual
cutting, joining, resizing and encoding. Deterministic and exact.

So the pattern is: Claude reads a transcript, decides the edit, writes the
FFmpeg commands, and runs them. No timeline, no dragging clips.

This also sets the honest limit. It is very good at repetitive, rule-based
work. It is not a replacement for a proper editor when the work is
creative. The consensus phrasing across sources is that AI clears the
repetitive layer and you still make the final creative calls.

=====================================================
WHAT THIS NEEDS
=====================================================
- Claude Code, not the desktop chat app. It needs to run commands and touch
files on the PC.
- FFmpeg and ffprobe installed and on the PATH. Free. This is the main
setup hurdle on Windows.
- Python and Node for the more advanced pieces.

=====================================================
THE STANDARD PIPELINE
=====================================================
1. INGEST. Normalise whatever came out of the recorder into one consistent
format and resolution. Log duration, codec and file size to a manifest so
later steps have something to read.
2. TRANSCRIBE. Get a timestamped transcript. This is the key move: it
converts video into text, and text is what Claude can actually reason over.
3. PLAN THE EDIT. Claude reads transcript plus timestamps and produces an
edit decision list - which segments stay, which go, in what order. This is
the step that saves the real time.
4. CUT. FFmpeg executes the list. One technical gotcha worth knowing: cuts
have to land on keyframe boundaries or you get black frames, and repeated
re-encoding degrades quality each pass.
5. POLISH. Final creative pass in a normal editor if needed.

=====================================================
THE FEATURES MOST RELEVANT TO ME
=====================================================
- DEAD AIR REMOVAL. FFmpeg can detect silences automatically
(silencedetect) and they can be cut in bulk. For a 90 minute webinar
recording with pauses, screen-share fumbling and "can everyone hear me",
this alone could be worth the setup.
- CLIPPING FOR SOCIAL. Give Claude the transcript and ask which segments
make the strongest short clips, then cut those automatically. Directly
applicable to the monthly .ai webinars and Boot Camp recordings.
- REFRAMING. Automatic conversion to vertical aspect ratios for shorts.
- AUTO CHAPTERS. Generate chapters based on what is actually discussed
rather than mechanical time splits. Useful for long webinar uploads.
- SUBTITLES. Generate and burn in captions.
- AUDIO NORMALISATION. Levels matched across recordings so the channel
sounds consistent.
- REMOTION. A tool for building video elements as code (React). Intros,
lower thirds, branded outros defined once and re-rendered forever with
different text. Real potential for consistent DIY Investors branding across
every upload, but it is a proper build, not an afternoon.

=====================================================
WHERE THIS FITS WITH WHAT I ALREADY HAVE
=====================================================
The ai4inv-webinar-processor skill already handles the post-recording
documentation side. This would extend the same pipeline backwards into the
recording itself: trim the dead air, cut the clips, generate the chapters,
then hand off to the existing skill.

Biggest single win to test first: automated silence removal on one webinar
recording. Small, measurable, and if it works it saves time every single
month.
